# Анализ результатов

Эта часть работает с уже сохранёнными результатами. Она не открывает браузер и не запускает обработку изображения. Её задача состоит в том, чтобы собрать отдельные измерения в таблицы и помочь сравнить подходы.

## Проверка входных данных

analyze.py обрабатывает одну завершённую серию.

Сначала он проверяет число прогонов, соответствие плану, отсутствие ошибок и контрольные суммы манифестов.

Незавершённые серии и старые записи без environment.json отклоняются.

Данные разных серий автоматически не объединяются.

## Запуск

Из корня проекта выполните команду, подставив имя нужной серии.

    make analyze BATCH=results/raw/имя-серии

Для анализа нужны Docker Compose и make. Python и библиотеки устанавливаются внутри контейнера.

requirements.txt фиксирует версии NumPy, SciPy, pandas и Matplotlib.

Версии транзитивных зависимостей отдельным lock-файлом не закреплены.

## Таблицы и графики

Результаты обработки сохраняются в *results/processed*. Имя папки совпадает с именем исходной серии.

| Файл | Содержимое |
| --- | --- |
| *runs.csv* | Одна строка для каждого прогона |
| *summary.csv* | Число наблюдений, медиана, межквартильный размах и доверительный интервал |
| *comparisons.csv* | Результаты попарного сравнения подходов |
| PNG-файлы | Распределение показателей и их изменение по порядку запуска |

Для временных показателей дополнительно строится ECDF. Данный график показывает долю прогонов, время которых не превышает выбранного значения.

## Статистическая обработка

Для интервала медианы используется перцентильный bootstrap с 10 000 повторными выборками и доверительной вероятностью 95%. Сид анализа фиксируется отдельно.

При одном наблюдении интервал не рассчитывается.

У постоянной выборки он совпадает с единственным наблюдаемым значением.

При этом систематическая ошибка измерения всё равно возможна.

Три временные метрики сравниваются между подходами внутри одного сценария двусторонним критерием Манна-Уитни. Используется асимптотический расчёт с учётом совпадающих значений.

Для оценки размера эффекта рассчитывается дельта Клиффа. Положительное значение означает более высокие показатели у подхода a.

Поправка Холма применяется ко всем рассчитанным сравнениям временных метрик серии.

Сравнения выполняются только для основной серии и при наличии не менее десяти наблюдений в каждой группе.

Это правило выбранного плана, а не гарантия достаточной статистической мощности.

Отсутствие значимого различия не доказывает эквивалентность.

Критерий сравнивает распределения, поэтому его результат нельзя без дополнительных условий трактовать как проверку только медиан.

## Метаданные анализа

analysis-manifest.json сохраняет версии основных библиотек, параметры анализа и SHA-256 входных файлов и скрипта.

Повторная обработка обновляет файлы в каталоге соответствующей серии.

## Как читать показатели

Линейная память WASM не равна общей памяти браузера.

wasmFetchedBytes учитывает размеры полученных данных, в том числе из браузерного кэша.

Суммарное время отдельных инициализаций не равно полному времени конкурентного сценария.

## Тесты и проверка стенда

test_analysis.py проверяет статистические функции и обработку входных данных.

test_validation.py проверяет A/A, тренд и предупреждения о ресурсах.

Тесты выполняются при сборке контейнера.

Команда make validate с параметром BATCH запускает обычный анализ и затем validate_stand.py. Подробности этой проверки описаны в VALIDATION.md.
