# Контейнеры стенда

Контейнер запускает программу вместе с нужным ей окружением.

Образ содержит файлы и настройки для такого запуска. Из одного образа можно создать несколько контейнеров.

Docker Compose описывает, какие контейнеры нужны проекту и как они соединяются.

## Сервисы и образы

Файл *docker-compose.yml* задаёт состав стенда и параметры запуска его сервисов.

| Сервис | Назначение |
| --- | --- |
| web | Выдача приложения через nginx |
| wasm-delivery | Централизованная доставка WASM-файла |
| checks | Выполнение функциональных проверок |
| experiment | Проведение серии измерений |
| analysis | Обработка сохранённых данных |

Dockerfile собирает приложение на Node.js 24.15.0, устанавливает зависимости через npm ci, запускает тесты и создаёт сборку.

Для серверов используется nginx 1.27.5.

Браузерный образ основан на Playwright 1.55.0 и содержит Chromium. Node.js копируется в него из этапа сборки.

Образ анализа описан отдельно в analysis/Dockerfile.

## Доставка файлов и адреса

web.conf направляет запросы /delivery/ в отдельный контейнер.

delivery.conf задаёт выдачу WASM с MIME-типом application/wasm.

У обоих серверов есть /health.

Служебные заголовки позволяют проверить, какой сервис ответил на запрос.

На компьютере приложение доступно по адресу http://127.0.0.1:4175.

Браузерный контейнер использует сетевую область web и обращается к http://127.0.0.1:8080.

Это сохраняет доступ к Web Crypto через localhost.

Процессы и файловые системы контейнеров остаются отдельными.

## Ограничения ресурсов

web ограничен одним CPU и 128 МиБ памяти, wasm-delivery половиной CPU и 64 МиБ.

У checks квота 2 CPU, 2 ГиБ памяти и 512 МиБ для /dev/shm.

Квота experiment задаётся переменной EXPERIMENT_CPUS, значение по умолчанию равно 4.

В основных сериях отчёта использовалось значение 6.

Эти квоты не резервируют физические ядра.

## Запуск и остановка

Команда make up собирает и запускает серверы. make smoke проверяет сервисы, доставку файла и обработку изображения.

make check запускает браузерные тесты.

Для остановки используется make down.

Основной эксперимент с квотой из отчёта запускается так.

    EXPERIMENT_CPUS=6 make experiment

Состояние контейнеров можно посмотреть через docker compose ps, сообщения серверов через docker compose logs --tail=100 web wasm-delivery.

## Сохранение данных

Файлы results и test-results подключаются с компьютера, поэтому сохраняются после завершения контейнеров.

У analysis исходные измерения доступны только для чтения.

В образ не включаются локальные зависимости, результаты, Git и файлы окружения.

## Окружение измерений

Идентификаторы использованных образов записываются в манифест серии.

Фиксированный тег версии сам по себе не гарантирует одинаковый образ при каждой сборке.

Браузерный контейнер предназначен для своего стенда и работает от root без браузерной песочницы.
