# Запуск эксперимента

Для автоматического выполнения эксперимента используется раннер. Данная программа открывает браузер, запускает сценарии приложения и сохраняет полученные показатели.

Обработка пикселей остаётся внутри браузера. Раннер управляет порядком действий, чтобы для разных подходов выполнялась одна и та же процедура.

## План прогонов

plan.mjs читает конфигурацию, проверяет параметры и составляет все сочетания подходов, сценариев и повторений.

Порядок перемешивается с заданным сидом. При одинаковой конфигурации и сиде план повторяется.

Сид не меняет исходное изображение.

| Конфигурация | Состав серии |
| --- | --- |
| *configs/experiment.json* | Основная серия из 90 прогонов |
| *configs/quick.json* | Девять прогонов для проверки запуска |
| *configs/aa.json* | Десять повторений одной конфигурации |

В A/A-конфигурации нельзя задавать несколько подходов или сценариев. Здесь проверяется разброс результатов при одинаковых параметрах.

## Подготовка запуска

launch.mjs выполняется на компьютере пользователя. Он получает Git-коммит, состояние рабочей копии, характеристики компьютера и Docker, идентификаторы образов и ограничения ресурсов.

Эти данные сохраняются до запуска браузерного контейнера.

Для основной серии нужен коммит и чистая рабочая копия.

Проверочную серию можно выполнить с изменениями, но они отмечаются в метаданных.

## Выполнение серии

run-experiment.mjs работает в контейнере. Он проверяет сервисы и контрольную сумму конфигурации, затем выполняет план.

Каждый прогон получает новый процесс Chromium и новый контекст браузера.

Раннер открывает страницу и вызывает __imageLabHarness.runScenario с выбранными параметрами.

После выполнения сохраняются исходный ответ приложения, счётчики, время, параметры и версия браузера.

Проверяются отсутствие ошибок, число экземпляров и операций.

Для последовательного сценария также проверяются размер результата и совпадение контрольных сумм.

При ошибке серия останавливается, а запись неуспешного прогона сохраняется.

Предварительного прогрева WASM нет.

Новый браузер исключает повторное использование его runtime и HTTP-кэша, но не сбрасывает кэши серверов и операционной системы.

Время сценария измеряется внутри приложения и не включает запуск браузера.

## Контроль ресурсов

resources.mjs считывает процессорное время Node.js и счётчики cgroup контейнера.

Записываются показатели за выполнение сценария и за запуск браузера вместе со сценарием. Время этих интервалов отличается от времени внутри страницы.

Недоступный мониторинг записывается как отсутствующий, а не как нулевая нагрузка.

## Сохранённые файлы

В results/raw создаётся отдельный каталог серии.

В нём находятся config.json, plan.json, summary.json, environment.json, build-artifacts.json и записи run-0001.json и далее.

summary.json показывает состояние серии.

Каждая запись прогона ссылается на environment.json и его SHA-256.

Отдельный environment-UUID.json в корне raw сохраняется ещё до запуска контейнера.

## Команды запуска

Команды make quick, make aa и make experiment выполняются из корня проекта.

Для квоты основного эксперимента используйте EXPERIMENT_CPUS=6 перед командой.

Другую конфигурацию можно передать через CONFIG.

    make experiment CONFIG=configs/quick.json

## Тесты

Тесты плана и ресурсов запускаются командой.

    node --test runner/plan.test.mjs runner/resources.test.mjs

После окончания серии серверы продолжают работать. Их останавливает make down.

Наличие полного манифеста само по себе не подтверждает достоверность результатов. Для этого по сохранённым данным оцениваются нагрузка, стабильность и повторяемость.
