# Обёртка для работы с WASM

Для взаимодействия приложения с WASM используется JavaScript-обёртка. Она принимает изображение и параметры операции, подготавливает данные и вызывает нужную функцию.

За счёт этого микрофронтендам не требуется самостоятельно выделять память и обращаться к её адресам. Данная логика находится в одном месте.

## Передача данных

image-runtime.ts связывает приложение с WASM. Методы filter, resize, flip, rotate90 и analyze принимают ширину, высоту и массив RGBA.

Обёртка проверяет данные, выделяет память внутри WASM, копирует пиксели, вызывает функцию и возвращает результат в JavaScript.

## Загрузка и инициализация

Загрузка начинается при первом обращении. Сначала читается manifest.json, затем проверяется версия API, загружается WASM и сверяются размер и SHA-256.

После этого создаётся экземпляр и проверяются его функции.

Проверка хеша подтверждает соответствие файлу манифеста, но не подлинность самого манифеста.

Первые одновременные вызовы ждут один Promise. Поэтому один runtime не создаёт несколько экземпляров при конкурентных обращениях.

После ошибки Promise сбрасывается и загрузку можно повторить.

Разные runtime остаются независимыми, даже если используют одинаковый URL.

## Проверка аргументов

Размеры изображения должны быть целыми и положительными, не больше 16 384 по каждой стороне и 16 777 216 пикселей в сумме.

Длина RGBA равна ширине, умноженной на высоту и на четыре.

Допустимый сдвиг яркости составляет от -255 до 255, коэффициент контраста от 0 до 10 000.

## Работа с памятью

Обработка данных выполняется в определённом порядке.

1. До ожидания загрузки создаётся копия входного изображения.
2. После инициализации сбрасывается указатель выделения памяти.
3. Данные размещаются в памяти WASM и передаются вычислительной функции.
4. Полученный результат копируется в отдельный JavaScript-массив.

Такая копия сохраняется при следующем использовании или увеличении памяти WASM.

Между выделением памяти и копированием результата нет await.

Этот участок выполняется в одном потоке без переключения на другую операцию.

Такая организация подходит для текущего приложения, но не является синхронизацией нескольких Web Workers.

## Общий экземпляр

shared-runtime.ts хранит общий runtime в отдельном ES-модуле.

Микрофронтенды импортируют один адрес этого модуля и получают один объект.

Сброс общей среды выполняется между сценариями, когда незавершённых операций нет.

## Показатели

В диагностике initializationAttemptCount считает попытки подготовки, а successfulInitializationCount успешные инициализации.

wasmInstanceCount показывает число готовых экземпляров, wasmLinearMemoryBytes текущую ёмкость линейной памяти.

wasmFetchCount считает вызовы загрузки WASM. wasmFetchedBytes суммирует размеры прочитанных тел ответов.

Эти показатели не равны числу сетевых передач и объёму трафика, поскольку ответ может прийти из кэша.

Запросы манифеста в них не входят.

initializationDurationMs включает загрузку, проверку хеша, компиляцию и создание экземпляра.

operationDurationMs включает выделение памяти, передачу данных, вычисления и копирование результата.

Проверка входа и ожидание инициализации в это время не входят.

operationCount считает завершённые операции, lastOperationDurationMs относится к последней операции одного runtime.

## Тесты

Команда npm run test:runtime из корня проекта собирает WASM, проверяет TypeScript и запускает тесты обёртки.

Они выполняются в Node.js с настоящим WASM-модулем, но загрузка файла заменена тестовой функцией fetch.

Работа HTTP и браузерного кэша проверяется отдельно.
