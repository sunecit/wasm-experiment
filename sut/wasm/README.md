# Вычислительный WASM-компонент

В данном каталоге реализованы вычислительные операции над изображением. Функции получают параметры и адреса данных, после чего выполняют обработку пикселей.

Результат остаётся в памяти WASM. Работа с интерфейсом и передача данных выполняются в других частях приложения.

## Исходный код и сборка

image-core.wat содержит вычислительные функции в текстовом формате WebAssembly. build.mjs компилирует его с помощью wabt и создаёт dist/image-core.wasm.

Рядом появляется manifest.json с размером файла, контрольными суммами, версией API и компилятора.

## Изображение и операции

Компонент принимает адреса данных в собственной линейной памяти. Он не обращается к странице или сети.

Изображение хранится построчно в формате RGBA. Каждый пиксель занимает четыре байта.

Цветовые фильтры сохраняют альфа-канал.

| Функция | Выполняемая операция |
| --- | --- |
| grayscale | Замена RGB средним значением трёх каналов с округлением вниз |
| invert | Вычитание каждого цветового канала из 255 |
| brightness | Изменение яркости с ограничением результата диапазоном от 0 до 255 |
| contrast | Изменение отклонения цветового канала от значения 128 |

Для contrast коэффициент 1000 сохраняет исходный контраст.

resize_nearest меняет размер методом ближайшего соседа. flip_horizontal и flip_vertical отражают изображение на месте. rotate90 поворачивает его по часовой стрелке и записывает результат в отдельную область.

Контраст и поворот доступны в ядре, но не входят в основные сценарии эксперимента.

## Анализ изображения

Функция analyze считает суммы RGB, минимальное и максимальное значения цветовых каналов, число пикселей и контрольную сумму FNV-1a по RGBA-данным.

Результат занимает 40 байт в формате little-endian.

Суммы R, G и B записываются как uint64 со смещениями 0, 8 и 16.

Минимум, максимум, контрольная сумма и число пикселей записываются как uint32 со смещениями 24, 28, 32 и 36.

FNV-1a используется для сопоставления изображений, SHA-256 для проверки самого WASM-файла.

## Выделение памяти

Начальная память состоит из четырёх страниц по 65 536 байт.

Функция alloc выделяет область с выравниванием до восьми байт и при необходимости увеличивает память.

reset_allocator возвращает указатель выделения к началу рабочей области. Данные при этом не очищаются, а размер памяти не уменьшается.

Проверка размеров и аргументов выполняется в TypeScript-обёртке.

При прямом вызове функций нужно самостоятельно обеспечить корректные адреса, положительные размеры и длину RGBA, кратную четырём.

Входная и выходная области resize_nearest и rotate90 не должны пересекаться.

После роста памяти JavaScript-представления буфера нужно создавать заново.

## Проверка компонента

Для сборки и проверки из корня проекта выполните.

    npm ci
    npm run test:wasm

Тесты сравнивают результаты с заранее известными пикселями, проверяют альфа-канал, яркость, геометрию, анализ и рост памяти.

Последовательная обработка изображения 640 × 420 также сравнивается с независимым расчётом на JavaScript.
