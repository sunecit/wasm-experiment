# Исследуемое приложение

Каталог *sut* содержит приложение, на котором проводится эксперимент. Обозначение SUT используется для объекта исследования.

Приложение можно открыть в браузере и проверить вручную. При автоматическом запуске те же действия выполняет программа управления экспериментом.

## Файлы приложения

Для реализации интерфейса используются следующие файлы.

| Файл | Назначение |
| --- | --- |
| *host/index.html* | Структура страницы |
| *host/style.css* | Оформление элементов интерфейса |
| *host/main.ts* | Подключение микрофронтендов и управление изображением |
| *host/sample.ts* | Создание исходного изображения |
| *host/results.ts* | Отображение результатов обработки |

## Микрофронтенды и подключение WASM

Микрофронтенды находятся в mfes/filters, mfes/transform и mfes/analysis. Первый меняет цвета, второй изменяет размер и отражает изображение, третий считает характеристики пикселей.

Каждый собирается отдельно в remoteEntry.js и регистрирует свой HTML-элемент. Они подключаются как ES-модули.

Module Federation в этом проекте не используется.

Файл mfes/common.ts содержит общий интерфейс взаимодействия с основным приложением и выбор среды выполнения.

В local каждый микрофронтенд получает собственный runtime и отдельный адрес WASM.

В server адрес общий, но runtime остаются независимыми.

В shared используется один объект из runtime/shared-runtime.ts.

## Сборка

build.mjs собирает страницу, микрофронтенды и общий runtime.

Затем он копирует WASM и манифесты в нужные каталоги. В dist/build-artifacts.json записываются размеры и SHA-256 файлов.

Все копии WASM должны совпадать.

## Сценарии и измерение времени

Последовательный сценарий выполняет фильтр, уменьшение и анализ.

Конкурентный сценарий передаёт одно исходное изображение двум операциям через Promise.all. Их результаты показываются отдельно.

Это проверка первых одновременных обращений, а не параллельных вычислений на нескольких ядрах.

В сценарии повторных обращений анализ выполняется третьей операцией из пяти и относится к изображению на этом шаге.

Перед сценарием восстанавливаются изображение и runtime.

При ручной работе это не очищает HTTP-кэш браузера.

В эксперименте раннер создаёт новый процесс браузера на каждый прогон.

Счётчики суммируются по отдельным runtime, поэтому общий объект не учитывается трижды.

scenarioDurationMs измеряется после сброса состояния и до вывода результата. Время запуска браузера и загрузки страницы в него не входит.

Интерфейс __imageLabHarness.runScenario позволяет раннеру запускать тот же сценарий без нажатия кнопок.

## Локальный запуск

Для локального просмотра нужны Node.js 24 и зависимости проекта. Из корня выполните.

    npm ci
    npm run build
    npm run preview

Страница будет доступна по адресу http://127.0.0.1:4174. Сервер останавливается сочетанием Ctrl+C.

Этот вариант обслуживает все ресурсы через Vite и предназначен для разработки.

В эксперименте используются отдельные контейнеры доставки.

## Тесты

Команда npm test проверяет WASM и его обёртку. npm run test:browser собирает приложение и проверяет сценарии через Playwright с установленным Google Chrome.

Тесты используют временный сервер на порту 4186. Если задан TEST_BASE_URL, они обращаются к указанному серверу. В контейнере используется Chromium.
